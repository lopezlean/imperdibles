# imperdibles.ar Phase 1, Data Side: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the shared foundation and the local data pipeline that reads prices from the Mercado Libre catalog API and store listings, matches exact models, applies the threshold, keeps price history, revalidates chosen candidates and stores a valid `ListaDeCandidatos` v1 in D1 every morning.

**Architecture:** One TypeScript codebase. Tasks 1 to 3 are the shared foundation (repo, tooling, contract, D1 schema, SQL client port, hook interface) that the output plan lists as its prerequisite. The data side runs on the owner's Mac as `imperdibles correr` and `imperdibles revalidar` (launchd), reads Mercado Libre and stores through an injected budgeted HTTP client, and writes D1 through the Cloudflare REST API behind `SqlClient`. It talks to the output side only through D1 rows and the `LocalOutputHooks` interface; the output plan owns that interface's implementation.

**Tech Stack:** Node 22, TypeScript 5 (strict, ESM), pnpm, Vitest, zod, cheerio, tsx, wrangler (D1 migrations), better-sqlite3 (tests only).

**Spec:** `docs/superpowers/specs/2026-11-10-fase-1-design.md` (context: `ROADMAP.md`). Companion plan: `docs/superpowers/plans/2026-11-10-output-side.md`.

## Global Constraints

- The folder is not a git repository yet: Task 1 runs `git init`. Conventional commits only (`feat:`, `fix:`, `test:`, `chore:`, `docs:`). Never add `Co-Authored-By` or any AI attribution to a commit.
- Strict TDD: every task writes the failing test first, runs it red, then green. Tests use recorded fixtures under `fixtures/` and injected fakes; no test calls Mercado Libre, a store, Telegram or Cloudflare.
- Secrets live in `.env` (local) and Wrangler secrets, created by the owner. Agents never create, read or print them, and never read `spike/.env` or `spike/.token`. Variable names: `ML_APP_ID`, `ML_CLIENT_SECRET`, `ML_REDIRECT_URI` (value `https://imperdibles.ar`), `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, `D1_DATABASE_ID`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_CHAT_ID`, `TELEGRAM_CHANNEL_ID`, `TELEGRAM_WEBHOOK_SECRET`, `PUBLISH_NOW_SECRET`, `WORKER_BASE_URL`. Steps that need a secret are marked **Owner runs** and the agent only prepares the command.
- Code, identifiers, comments, commit messages and plans in English. User-facing copy (terminal messages of `imperdibles`, bot texts, page, card, posts) in neutral Spanish, taken verbatim from the spec and the design files where they fix it.
- The contract (`ListaDeCandidatos` v1) and the D1 table, column and enum names are data formats fixed by the spec: keep their Spanish keys verbatim. All TypeScript identifiers we choose are English (`StoreAdapter.search` implements the spec's `AdaptadorTienda.buscar`).
- Affiliate links are stored and published verbatim, never resolved, shortened or rewritten; only host `meli.la` is accepted (output plan enforces it; the data side never touches `enlace_afiliado`).
- Cloudflare free plan: 10 ms CPU per invocation and per Cron Trigger, 50 subrequests per invocation, 5 Cron Triggers per account (this project uses 2). D1 free: 100.000 rows written per day.
- Mercado Libre: only `GET /products/search?site_id=MLA&status=active&q=`, `GET /products/{id}`, `GET /products/{id}/items` and `POST /oauth/token`. Never call `/sites/MLA/search`, `/items/{id}` or `/items/{id}/prices`; never scrape mercadolibre.com.ar.
- Money is integer pesos (`INTEGER`), list price, no shipping or installments. Dates use America/Argentina/Buenos_Aires (UTC-3, no DST) through `src/shared/time.ts`, never the Mac's zone.
- "Ante la duda, no se publica": when a step cannot decide (unknown seller, ambiguous match, missing price) it drops the item and logs why.
- `spike/` is throwaway: never import, extend or copy code from it.
- Shell commands in this plan use `bat`, `rg`, `fd`, `sd`, `eza` instead of `cat`, `grep`, `find`, `sed`, `ls`.
- Dependencies, `package.json`, `pnpm-lock.yaml`, `tsconfig.json` and `vitest.config.ts` are created in Task 1 and frozen afterwards. If a later task needs a new dependency, stop and ask the owner.
- Unverified items get a verification task early. Each outcome goes to `docs/verification/data.md` as `## Vn <title>` with date, what was checked, result and fallback applied.
- Deadline 27/11/2026. Order follows the ROADMAP calendar: Tasks 1 to 13 by 15/11 (candidate list), Task 14 by 18/11 (needed for the output side's dry runs by 20/11), Tasks 15 to 17 by 24/11, 25 to 27/11 fixes only.
- Commands: `pnpm test` (all), `pnpm vitest run <path>` (one file), `pnpm typecheck`.

## Review Focus

1. A spare part or accessory priced within 0.5 to 2.0 of the robot (base station, battery, "kit de repuestos para S40C") with the same brand and code must not be `alta`. Expected: `dudosa` by an accessory-word guard. Test in Task 9.
2. Prices with cents or odd formats (`329999.5` from the API, `$329.999,50` or `$ 329.999` in HTML) must never tilt toward a false pass. Expected: ML price rounded up, other stores rounded down. Tests in Tasks 7 and 8.
3. Running `imperdibles correr` twice on the same day (launchd plus a manual run) must not create a second candidate set or a second shortlist. Expected: refuses with a clear message unless `--forzar`. Test in Task 13.
4. At revalidation the other store's listing disappears, or a price changes but still passes. Expected: missing listing gives `invalidado`; a changed price updates the payload and clears `telegram_file_id` so no stale card is published. Test in Task 14.
5. A run near midnight UTC (for example 22:30 ART = 01:30 UTC next day) must stamp `fecha` with the ART date. Tests in Tasks 1 and 13.

### Task 12: Collection pipeline and reproduction run

**Files:**
- Create: `src/data/pipeline.ts`, `fixtures/runs/<recording-date>-aspiradoras-robot/**`
- Modify: `scripts/record-fixtures.ts` (complete `run <categoria>`)

**Interfaces:**
- Consumes: `MlCatalog`, `cheapestNewOffer`, `StoreAdapter`, `pickCatalogProduct`, `matchListings`, `extractModelCodes`, `normalizeBrand`, `buildCandidateList`, `BudgetExhaustedError`, `UpstreamError`, `StoreFormatError`, `MlPermissionError`, `MlAuthError`.
- Produces:

```ts
export type PipelineDeps = { catalog: MlCatalog; primary: StoreAdapter; secondary: StoreAdapter[]; rejected: (modeloId: string) => Promise<Set<string>>; now: () => Date; log: (event: string, data: Record<string, unknown>) => void };
export type PipelineResult = { list: CandidateList; listings: Listing[]; models: ModelRow[]; matches: MatchRow[]; estado: "ok" | "parcial"; skipped: { modelo_id: string | null; reason: string }[]; alerts: OwnerAlert[] };
export function runPipeline(deps: PipelineDeps, input: { corrida_id: string; fecha: string; category: Category; umbral_pct: number }): Promise<PipelineResult>;
```

Algorithm (spec §4.1, §4.2, decision 6 and 21):
1. `primary.search(term)` for each `category.terminos`; union deduped by `ref_externa`. Only the first page is read.
2. Per primary listing: no model code → skip `no_model_code`. `modelo_id = "<normalizeBrand(marca)>:<code>"`; keep the cheapest primary listing per `modelo_id`.
3. `catalog.searchProducts("<marca> <code>")` → `pickCatalogProduct`; no product → a `dudosa` match row with `regla: "parcial"`, `motivo` = reason; continue.
4. `catalog.getOffers(product.id)` → `cheapestNewOffer`; none → skip `sin_ofertas_nuevas`. Every offer read (all conditions) becomes a `Listing` for history.
5. For each secondary store: `search("<marca> <code>")`, `matchListings(product with ML price, listing)`, keep the cheapest `alta` per store.
6. Re-run `matchListings` for the primary listing with the ML price (price guard). Drop any rival whose `"<tienda>:<ref_externa>"` is in `rejected(modelo_id)`.
